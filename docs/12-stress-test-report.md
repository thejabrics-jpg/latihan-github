# 12 - Adverse-Market Stress Report (§36)

Deterministic arithmetic about the one thing that kills averaging strategies: what
the basket costs when price keeps moving against it while the EA keeps adding
layers. No slippage, no requotes, no partial fills, exact fills at the trigger
price - so every figure is a **floor**, not a forecast, and the real tail is
worse than what is printed here.

The tables are generated; do not edit them by hand.

```bash
python3 tools/stress_model.py                       # print
python3 tools/stress_model.py --emit-doc docs/12-stress-test-report.md
python3 tools/stress_model.py --layers 6 --base 0.02 --mult 2.0 --distance 450 \
        --entry 2350 --account 5000 --leverage 200  # your own settings
python3 tools/stress_model.py --json                # machine readable
```

Model source of truth: `MQL5/Include/XAU_AVG_PRO/{Averaging,Lots,Basket}.mqh`.
Entry reference for all scenarios: `2350.00` (a BUY basket - the SELL case is the
mirror image, since every formula in the model is direction symmetric).

## 1. Model and assumptions

| Assumption | Value | Source |
|---|---|---|
| Point size | 0.01 | XAUUSD digits=2 (`CSymbolSpec` reads it live) |
| Contract size | 100 oz | `SYMBOL_TRADE_CONTRACT_SIZE` |
| Money per point per 1.00 lot | $1.00 | contract x point |
| Commission | $3.50 round turn per lot | typical raw/ECN XAUUSD |
| Swap | $-12.00 per lot per night | long gold carry, see docs/09 |
| Lot flooring | floor to VolumeStep | `CSymbolSpec::NormalizeVolume` |
| Distance | max(clamped(ATR x mult or FIXED), spread x multiple) | `CAveragingEngine::MinimumSafeDistancePoints` |

The model deliberately ignores slippage and requotes, and it assumes every
order fills exactly at the trigger price, so it **understates** the real
damage. Every number below is a floor, not a forecast.

Two conventions matter when reading the tables:

1. Adverse excursions are measured from the **first entry price**, not from the
   basket average. After a full sequence the average sits far below the entry
   (BUY case), so a shallow dip is already profitable - the real risk is the
   deep tail, which is why the tables keep going to -2000 points.
2. The *instant floating* column is the loss created at the moment each new layer
   is filled. Averaging converts a winning basket into a losing one precisely
   because every new layer starts underwater, and it does so by `lot x distance`.

## 2. Reading the tables

* Scenario A is what the shipped defaults do. The basket never grows its
  volume, so the loss curve is linear in price and the cut-loss cap is
  reachable by design.
* B vs C: doubling the multiplier from 1.5 to 2.0 roughly triples the total
  volume at layer 6 and quadruples the loss at the same depth. That is the
  non-linearity the risk disclaimer in `docs/14-risk-disclaimer.md` is about.
* D shows why the ATR distance mode is safer in a volatile regime: levels are
  further apart, so fewer layers are added per dollar of adverse move - but the
  basket is *below* the market by more when it is done, so the recovery target
  is larger. There is no free parameter here.
* E models a gap: when one jump crosses several levels, `MinimumDistanceSpreadMultiple`,
  `MinimumSecondsBetweenAveraging` and `OneLayerPerBar` decide how many layers the
  EA actually adds. The single worst outcome is therefore bounded by
  `MaximumLayer x MaximumLotPerOrder`, not by the multiplier.

## 3. What the caps buy

| Cap | Effect in the model |
|---|---|
| `MaximumLotPerOrder = 0.2` | hard ceiling on any single layer; caps the growth of scenario C |
| `MaximumTotalLot = 1.0` | stops adding layers once the basket reaches the ceiling (flag `capped_by_total_lot`) |
| `MaximumLayer = 6` | bounds the sequence length, hence bounds the worst case |
| `MaximumCycleDrawdownPercent` / cut loss | converts an open-ended losing basket into a fixed money loss |

Reproduce any of these numbers with:

## 12.1 Conclusions drawn from the tables

1. **The multiplier is the risk, not the distance.** Comparing scenario B (x1.5)
   with scenario C (x2.0) at the same distance and the same number of layers: total
   volume and the loss at depth grow super-linearly, while the distance "safety"
   is identical. The default configuration therefore ships `LotMode=FIX`.
2. **`MaximumLotPerOrder` and `MaximumLayer` are the only caps that bound the
   worst case in arithmetic terms.** The tables show the cap biting (`capped by
   MaximumLotPerOrder`), which is why `docs/11.4` forbids optimising them.
3. **The cut loss is a target, not a floor.** The `gap jumps past the cut loss`
   row is the honest number: a jump of two distances through the trigger is a
   routine Monday-open event on gold. Size the account with that row.
4. **ATR-based distance (scenario D) does not reduce tail size by itself** - it
   reduces the *number of layers* per dollar of adverse move while increasing the
   depth at which each layer is taken. The useful effect is on layer count, which
   is why it is combined with `MinimumDistanceSpreadMultiple` (and the model shows
   that guard binding in scenario E where the spread is 210 points).
5. **Margin is never the first problem on the shipped defaults** (well under 1 %
   of a 10 000 account), but on a 500 account with `MULTIPLIER 2.0` and a 0.05
   base lot it reaches double-digit percentages of equity, and then
   `MinimumFreeMarginPercent` starts rejecting layers - which is the *correct*
   outcome, and precisely what a margin-call-avoidance test must show.

## 12.2 What would change these numbers (all of them make it worse, not better)

* real spread widening during the move (`docs/06.5` basket TP has to pay it);
* commission per side on the closing sweep (the model includes an estimate);
* swap for multi-day baskets (modelled at $12 per lot per night on longs);
* slippage on the layer entries in a fast market;
* a Monday gap open larger than two distances (scenario E is the tame version);
* a broker that rejects a close at the worst moment (the EA retries, but the
  market keeps moving while it does).

## 12.3 Reproducing from the EA itself

Run `tools/stress_model.py` with the same inputs your `.set` file uses; the
per-layer prices in the table are the levels the EA would compute for
`AveragingDistancePoints`/`ATRMultiplier`, so you can diff them against the
`[AVG] LAYER n opened … level=…` lines of a backtest or of a live session. If a
live sequence does not match the model, the difference is your broker's fill
quality - which is a fact about the broker, not a bug in the strategy.
